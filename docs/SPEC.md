# 体組成 × Apple Watch 健康アプリ 仕様書（v0.1）

## 1. 目的と成功指標

| 項目 | 現状（2026-09-30） | 目標（2027-03末 / 6か月） |
|---|---|---|
| 内臓脂肪レベル | 11（やや過剰） | **9 以下**（週中央値で2週連続） |
| 筋肉量 | 51.1 kg | **50.5 kg 以上を維持**（7日平均） |
| 体重 | 64.8 kg | 月 −0.5 kg 前後の緩やかな減少（急減させない） |

- 利用者：本人のみ（59歳・男性・167cm・誕生日 5月9日）。App Store 公開はしない。
- 「作ってよかった」の定義：**内臓脂肪レベルが下がり、筋肉量が落ちていないことを週単位で確認でき、来週やることが1〜2個に絞れる**こと。
- 医療診断はしない。表示はすべて「目安」として扱う。

## 2. 前提・制約

- 体組成計：TANITA DC-430A（業務用・レシート印字）。通信機能は使わない。
- 測定：ほぼ毎日、同じ時間帯（夜）に測定する。
- 開発：Mac あり、Apple Developer Program 登録済み。実装は Claude、動作確認は本人。
- 対象：iOS 17 以上（SwiftData を使用）、Apple Watch はデータ取得のみ（Watch アプリは作らない）。
- 手入力はレシート撮影のみ。食事・飲酒の記録は Phase 2 で検討する。

### 3.3 派生指標

- **トレンド値**：体重・体脂肪率・筋肉量の7日移動平均（測定が欠けた日は除外して計算する）。
- **内臓脂肪レベル（週）**：その週の測定値の中央値。整数でしか変わらないため、毎日の判定には使わない。
- **筋肉量ガード**：筋肉量の7日平均が開始時（最初の7日平均）から 1.0 kg 以上下がったら警告を出す。
- **Zone2 心拍範囲**：カルボーネン法で、安静時心拍（HRrest）の直近30日の中央値を使う。
  HRmax = 220 − 年齢、範囲 = HRrest + (HRmax − HRrest) × 0.60〜0.70。
  例：59歳・HRrest 60 の場合は 121〜131 bpm。設定画面で手動変更できるようにする。
- **年齢の切り替わり**：TANITA の推定値は入力した年齢に依存する。誕生日（5月9日）の前後は、グラフに目印を付ける（値の段差は体の変化ではない可能性がある）。
  - 今後の切り替わり：2027-05-09（59→60歳）。6か月目標の期限（2027-03末）より後なので、目標の判定には影響しない。
  - レシートに印字された年齢と、誕生日から計算した年齢が一致しない場合は、確認画面で警告する。

## 4. レシートの読み取り（OCR）

1. カメラで撮影する。ライブラリから選ぶこともできる。
2. Vision `VNRecognizeTextRequest` で読み取る（`recognitionLevel = .accurate`、`recognitionLanguages = ["ja-JP"]`）。処理はすべて iPhone の中で行う。
3. **項目名から数値を探す**：同じ行の右側（文字の位置で判定）にある数値を取り出す。
   - 正規化：全角を半角に変える。`64. 8` のように数字の間に入った空白を詰める。`O`/`o` は `0` に、`l`/`I` は `1` に置き換える（数値部分だけ）。
   - 似た項目名の取り違えを防ぐため、「脂肪量」と「除脂肪量」、「体脂肪率」と「脂肪量」のように、長い項目名から順に照合する。
4. **整合性チェック**（レシートの値は互いに計算で確かめられる）：

   | チェック | 式 | 許容誤差 |
   |---|---|---|
   | 体重の内訳 | 脂肪量 + 除脂肪量 ≒ 体重 | ±0.2 kg |
   | 体脂肪率 | 脂肪量 ÷ 体重 ≒ 体脂肪率 | ±0.3 %pt |
   | 除脂肪量の内訳 | 筋肉量 + 推定骨量 ≒ 除脂肪量 | ±0.2 kg |
   | BMI | 体重 ÷ 身長² ≒ BMI | ±0.2 |
   | 値の範囲 | 体重 30〜150、体脂肪率 3〜60、内臓脂肪 1〜59 など | – |

   いずれかのチェックに失敗した項目は、確認画面で赤く表示する。
5. **確認画面**：読み取ったすべての値を表示し、手で直してから保存する。チェックをすべて通った場合は「保存」ボタンを強調する。
6. **重複の防止**：`measuredAt` が同じ記録がすでにあれば、上書きするか確認する。
7. **過去の紙レシートは取り込まない**（2026-10-06 決定）。取り込みに時間がかかるわりに、変化が小さく得られる情報が少ないため。記録は 2026年10月の新規測定から始める。

## 5. 画面

1. **ホーム**：内臓脂肪レベル（今週 / 目標 / 開始時）、体重と筋肉量の7日トレンド、筋肉量ガードの状態、今週の運動・睡眠の要約。
2. **撮影**：カメラを起動し、読み取り後に確認画面を出す。
3. **グラフ**：体組成の各指標（移動平均と実測の点）と、Watch の指標を同じ時間軸で並べる。表示期間は 1か月 / 3か月 / 6か月 / 全期間。
4. **週次レポート**：Claude による振り返りを表示し、過去のレポートも一覧で見られる。
5. **設定**：目標値、Zone2 心拍範囲、HealthKit の権限、Claude API キー（Keychain に保存）、データの CSV 書き出し。

## 6. 週次レポート（Claude）

- タイミング：毎週日曜の夜に通知を出し、ユーザーが開いたときに生成する。
- 送信するのは**週ごとに集計した値だけ**とする。日ごとのデータや個人を特定できる情報は送らない。
  - 送信する値：体組成の週平均と開始時からの変化、内臓脂肪レベルの週中央値、歩数・エクササイズ時間・Zone2・睡眠・安静時心拍・HRV の週平均、目標値、直近4週の推移。
- 出力の形式：
  1. 今週の評価（3行以内）
  2. 先週と比べて目立った変化
  3. **来週の重点を1〜2個**。具体的で数値を含むもの（例：「Zone2 を週150分 → 180分」）。
- 制約：医療的な判断はしない。筋肉量ガードが警告を出している週は、減量を勧めずに筋力トレーニングと食事量の維持を優先する。
- API キーはユーザーが設定画面で入力し、Keychain に保存する。モデルと費用は実装時に決める。

## 7. 保存

- 1日に2回以上測定した場合は、その日の最後の測定をその日の代表値とする。ほかの測定も記録としては残す。

- SwiftData で iPhone 内に保存する（`BodyRecord`、`DailyActivity`、`WeeklyReport`）。
- Watch のデータは HealthKit から毎回読み直し、アプリ内には日ごとの集計のキャッシュだけを持つ。
- バックアップ：CSV の書き出し。iCloud への同期は後で検討する。
