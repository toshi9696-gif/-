# ut-scenario：テストシナリオの作成・更新

まず `ut-shared` を読み、あれば `00_plan.md` を読んで目的と対象者を確認する。

## 作成ルール
- タスクは**目的ベース**で書く。画面上のボタン名や操作手順を含めない（誘導になるため）。
  - 悪い例：「右上のメニューから設定を開いてください」
  - 良い例：「通知が多いと感じています。届く数を減らしてみてください」
- 参加者が状況を想像できる**シナリオ文**（背景・動機）を付ける。
- 各タスクに**成功条件**、**想定時間**、**観察ポイント**を決める。
- 簡単なタスクから始め、1 セッションのタスクは 3〜6 個にする。
- 質問は開かれた質問にし、誘導や「はい/いいえ」で答える質問は避ける。

## 01_scenario.md の構成
```markdown
# <テスト名> シナリオ（v1）
## 導入スクリプト（挨拶・趣旨・思考発話のお願い・同意確認）
## 事前質問
## タスク
### T1: <タスク名>
- シナリオ文：
- 成功条件：
- 想定時間：
- 観察ポイント：
- タスク後の質問：
## 事後質問・アンケート（SUS 10問 など）
## 締めのスクリプト
```

## 更新時
- 変更点を末尾の「変更履歴」に追記し、バージョン（v2…）を上げる。
- パイロットテストの結果を反映する場合は、どの観察を受けて何を変えたかを書く。
