# ut-analysis：テスト結果の分析・レポート作成

まず `ut-shared` を読み、`00_plan.md`、`01_scenario.md`、`02_sessions/*.md` をすべて読む。

## 分析手順
1. **定量の集計**：タスクごとの成功率（4区分）、平均所要時間、エラー数、SUS スコア（平均と 68 点基準との比較）。
2. **発見事項の抽出**：複数の参加者に共通する問題をまとめる（アフィニティ分類）。
3. **深刻度の付与**：致命的 / 重大 / 軽微 / 改善提案。影響を受けた人数と、タスク達成への影響で判断する。
4. **根拠の紐づけ**：各発見事項に、参加者 ID と発言・行動の引用を付ける。
5. **改善提案**：発見事項ごとに具体案と優先度（高/中/低）を書く。
6. 当初の「検証したい問い」に答える形で結論をまとめる。

## 03_report.md の構成
```markdown
# <テスト名> レポート
## サマリー（結論 3 行・重要な発見トップ 3）
## テスト概要（目的・参加者・日程・方法）
## 定量結果
| タスク | 成功 | 補助付き | 失敗 | 平均時間 |
## 発見事項
### F-01 <タイトル>（深刻度：重大／該当 3/5 名）
- 現象：
- 根拠：P2「…」、P4 …
- 原因の仮説：
- 改善提案：
## うまくいっていた点
## 改善提案の優先順位表
## 次のアクション・追加検証
```
- 人数が少ない場合、数値は傾向として扱い、断定しない。
- 必要なら `dataviz` スキルでグラフを作り、`pptx` や `docs` スキルで共有用の資料にする。
