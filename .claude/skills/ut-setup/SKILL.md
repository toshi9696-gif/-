# ut-setup：ユーザーテストの環境設定

まず `ut-shared` スキルの共通ルールを読む。

## 手順
1. **ヒアリング**（不足があれば質問する。分かる範囲は仮置きして進める）
   - テスト対象（アプリ/Web/プロトタイプ、URL やビルド）
   - 検証したい問い（例：新規登録を迷わず完了できるか）
   - 対象ユーザー像と人数（定性テストは 5 名前後を目安）
   - 実施形式・日程・所要時間（1 セッション 45〜60 分が目安）
2. **環境チェックリストを作る**
   - 対象：テスト用アカウント、テストデータ、ビルド/URL の固定
   - 機材：PC/スマホ実機、画面共有・録画ツール（Zoom、Lookback、Maze 等）、マイク
   - 会場：静かな部屋、ネット回線、予備機
   - 書類：同意書、謝礼、守秘義務
3. **リハーサル計画**：本番前にパイロットテストを1回行う。
4. `user-tests/YYYY-MM-DD_<テスト名>/00_plan.md` を出力する。

## 00_plan.md のテンプレート
```markdown
# <テスト名> 計画
## 目的と検証したい問い
## 対象ユーザー・募集条件・人数
## 実施形式・日程・所要時間
## テスト対象（バージョン/URL）
## 環境・機材チェックリスト
- [ ] ...
## 役割分担（モデレーター／記録係／見学者）
## 同意・謝礼
## リスクと対策
```
次は `ut-scenario` でシナリオを作ることを案内する。
